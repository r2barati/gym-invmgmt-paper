Overview

Same contract, different stress

Head-to-head inventory results depend on the test conditions almost as much as on the policy. gym-invmgmt evaluates optimization, heuristic, reinforcement-learning, imitation and LLM controllers under one shared contract: the same transition dynamics, reward, action bounds and KPIs. It then varies the stress conditions, including network topology, demand dynamics, customer goodwill and shortage handling, across a 22-scenario main grid. Four supplementary MARL-mode rows keep the published artifact complete.

% of Oracle is computed per episode against the Oracle on the same demand seed. Whiskers are 95% intervals from a stratified bootstrap that resamples seeds within each scenario (1,000 resamples), so they measure seed noise for a fixed set of scenarios. IQM is the mean of the middle 50% of episodes, which is less sensitive to rare collapses (Agarwal et al., 2021). Informed agents read the true mean of the demand process; blind agents estimate it from realized demand.

Environment

The contract every method plays under

One Gymnasium environment, CoreEnv, defines the dynamics, reward and KPIs for every agent. Agents differ only in how they choose orders.

One period, in order

  1. Place orders. One quantity per reorder link. Each order is filled only up to the supplier's on-hand stock, or a factory's production capacity.
  2. Receive deliveries. An order placed at period t on a link with lead time L arrives at period t + L; until then it is pipeline inventory.
  3. Realize demand. Customers buy from the retailer's stock. Unmet demand is either carried as backlog or lost, depending on the scenario.
  4. Book profit. Sales revenue minus procurement, holding on hand and in transit, factory operating cost and the backlog penalty, summed over all nodes.
  5. Observe. The agent sees last period's demand and backlog, on-hand inventory, and the arrival schedule of its open orders.
Horizon
30 periods per episode
Action
Continuous order quantities, one per reorder link: 11 on the base network, 3 on the serial chain
Observation
71 values on the base network, 15 on the serial chain
Reward
System-wide profit for the period
Demand model (retail link)
μt = μ0 · (1 + 0.05t) · (1 + 0.5 sin(2πt / 30)) · (2 if t ≥ 15) · gt
Dt ~ Poisson(μt),  μ0 = 20

Trend, seasonality, the shock that doubles demand from period 15, and goodwill gt are each switched on per scenario. Goodwill falls 10% after a period with unmet demand and otherwise grows 1%, bounded to [0.2, 2]. The M5 scenarios replay Walmart item FOODS_3_382 at store CA_3 (days d_1841 to d_1870), scaled to mean 20, without added noise.

Get started

Run it in two minutes

Try it in the browser

The getting-started notebook runs the environment and benchmarks a policy in about five minutes, on CPU, with no checkpoints.

Install the environment

The standalone package registers two Gymnasium environments.

pip install gym-invmgmt
import gymnasium as gym
import gym_invmgmt  # registers the environments

env = gym.make("GymInvMgmt/MultiEchelon-v0")
obs, info = env.reset(seed=0)
for t in range(30):
    action = env.action_space.sample()  # your policy here
    obs, reward, terminated, truncated, info = env.step(action)

Bring your own network

Load any topology from YAML. The package ships the four shown above.

import os, gym_invmgmt

path = os.path.join(os.path.dirname(gym_invmgmt.__file__), "topologies", "diamond.yaml")
env = gym_invmgmt.make_custom_env(path, num_periods=30)

Reproduce the paper

Download the released checkpoints and rerun the canonical benchmark.

git clone https://github.com/r2barati/gym-invmgmt-paper
cd gym-invmgmt-paper
pip install -e ".[all]"
bash download_weights.sh

cd benchmarks
python3 run_benchmarks.py --agent ALL --seeds 10
python3 verify_publication_ready.py --quick

Use real demand data

Adapters in gym_invmgmt.data_adapters turn M5-style wide sales files, long-format demand CSVs and node/edge tables into environment inputs. The test suite checks them on M5, Rossmann-style and Favorita-style data.

Compare your own agent

Write a class with the same call convention as the shipped agents and declare its information tier. The evaluator runs only your agent on the 22 main scenarios and 10 seeds, then compares it seed by seed against the published per-seed results, so the base install is enough: no solver, checkpoints or GPU.

class MyAgent:
    def __init__(self, view, seed):
        self.view = view   # spaces, network, observation layout

    def get_action(self, obs, t):
        return ...         # array shaped like view.action_space
python3 benchmarks/evaluate_custom.py \
    --policy path/to/my_agent.py:MyAgent --tier blind

Blind agents see realized demand only; informed agents can also call view.demand_mean(t). The output includes paired profit differences with 95% intervals and the gap to the Oracle. benchmarks/example_custom_agent.py is a working blind agent to start from.
